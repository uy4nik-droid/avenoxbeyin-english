# AvenoxBeyin V3.8.1

Performance only. Using the measurement contract in #233, three bottlenecks on the hook path were removed; the privacy gates and conflict visibility did not change, and the only difference in behavior is below (topic anchor in a very large vault). Prompts after one that already received context in a session now get their context in a third of the time in a 1,500-note vault, and in about 30% of the time at 10,000 notes; the session-start companion context and the background sync that runs on every prompt also got shorter.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. Updating from a V3.8.0 install reports `trust_review_required: false`. For a fresh install, download `beyin-v3-3.8.1.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

## What got faster

Measurement: `scripts/perf_v3.py`, synthetic vault, same fixture, 5 repetitions, median; macOS, Apple M5, Python 3.14, APFS. Detailed tables and the Windows measurements are in #233.

| Case | 1,500 notes | 10,000 notes |
| --- | --- | --- |
| Second concrete prompt in a session (foreground, no worker) | 627 ms -> 212 ms | 3,977 ms -> 1,172 ms |
| Vague follow-up prompt ("elaborate on this a bit more") | 635 ms -> 233 ms | 3,835 ms -> 1,411 ms |
| SessionStart (foreground, no worker) | 133 ms -> 89 ms | 324 ms -> 123 ms |
| Warm sync on an unchanged vault | 339 ms -> 261 ms | 2,057 ms -> 1,780 ms |

- **Topic continuity (#244):** when a topic anchor existed in the session, every concrete prompt re-read and hashed the whole vault before checking whether it could be a follow-up. Now the predicate that looks only at the words runs first; on a real follow-up prompt, only the recorded sources (at most 3) pass through the same gates. A valid topic anchor that could previously be dropped arbitrarily in vaults larger than 10M characters is now preserved.
- **Background sync (#245):** the per-note SQL query and write for unchanged notes were removed, and the file path is no longer resolved twice. The file's two reads and the "changed while being scanned" check remain as they were. On Windows, two workers could count the same event twice; the queue acknowledgement is now under the index lock.
- **Session-start companion context (#246):** every record in the vault was being resolved to find a few files such as Core, Kurallar and Last-Session; now only the candidate records are.

On Windows, every hook event carries an extra cost of ~180-200 ms because of the PowerShell `-EncodedCommand` launch (the price of carrying Unicode paths safely); this did not change in this release and is noted in #233.

## For developers

- `scripts/perf_v3.py` (#241): a stdlib-only measurement tool; a synthetic vault generator, cold process, sync, lock, and median/p95 for each hook event, raw results, fixture hash and machine information. It is not part of the release package.
- `tests/v3_perf_budget_test.py` (#247): a regression gate that measures operation counts, not time; CI fails if a vault scan on the hook foreground, JSON decoding that grows with the note count, unnecessary reading by continuity, or per-note SQL comes back.

## Verification

- Before release, 1,012 V3 tests passed on Python 3.11 and 3.14, also with the user's `BEYIN_*` settings on; the frozen retrieval gate (development 10/10, holdout 6/6) passed. The release pipeline verifies the same ZIP on Windows, macOS and Linux.
- A synthetic vault installed with the published V3.8.0 package was updated to this release (`trust_review_required: false`), and `verify_v3_release.py` passed with the V3.8.0 base. After rollback to V3.8.0, `doctor` and the SessionStart hook ran without errors.
