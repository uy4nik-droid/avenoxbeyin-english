# AvenoxBeyin V3.1.0

It is now easier to notice and install a new release: a daily release check, a single notification per session, and a safe update with the existing single command.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

V3.0.2 users must run this command first; the notification code arrives with V3.1.0. Then open a new client session. If the hook definition changed, complete the trust review the client shows. For a fresh install, download `beyin-v3-3.1.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

## What's new

- At session start, a separate process checks the official stable release once a day. The main session does not wait on the network; a single short notification is shown for the same release. The result of the first check appears in the next session or in the `doctor` output.
- `update --check --metadata-only` shows release information without downloading the ZIP and without running package code. The old `update --check` keeps the full package check.
- Manage the automatic release check with `preferences --update-notifications off/on`; silence a single release with `update --dismiss X.Y.Z`. `BEYIN_UPDATES_OFF=1` is the emergency off switch.
- The external SHA-256 of the downloaded ZIP is verified before any package code runs. A corrupted or incomplete package is not installed. Use `recover` for an interrupted operation and `rollback` to undo the last system update.
- `context --no-sync` opens the existing index read-only. It does not create a missing runtime; it excludes changed or deleted sources; it writes no bytecode/cache. To see newly added sources you need a normal context or sync.

The update check does not send notes, prompts, session IDs or account tokens; it does not call a model and does not install anything on its own. The notification preference lives outside the vault; after a rollback to an older release, the old settings reader keeps working.

## Other changes since V3.0.2

- Hermes and OpenCode connections; a local engine shared with the existing clients.
- Optional Jev context/answer evaluation and an on/off/shadow switch. It is off by default. If automatic Jev context is separately enabled, the prompt plus up to eight public/internal note titles and their first 600 characters go to the provider; this is a separate preference from the release check.
- Better source retrieval with Turkish suffixes and Obsidian date fields; avoiding irrelevant results in automatic context.
- Companion continuity and Journal selection fixes; frontmatter comments and template fields; Windows CRLF and review of customized legacy installs; preservation of user skill content.

The global hook bridge (#41) is not included in this release. The update does not forcibly change personal notes or user-owned custom scripts; it stops on a managed-file conflict.

## Verification

The release pipeline builds the ZIP once. The same package is tested on Windows, macOS and Linux with Python 3.11 and 3.13: clean install, migration from the published V3.0.2, no-op, read-only, rollback, recovery of an interrupted operation, and preservation of user notes. The V3 tests and synthetic retrieval gates also run before release. After release, the asset is downloaded again and its hash and installation are verified.

These tests verify synthetic installs and client adapter contracts; they do not mean that every real Codex Desktop/Claude/OpenCode/Hermes session has been tried one by one.
