# AvenoxBeyin V3.2.1

Fixes the `invalid legacy skill hashes` error that blocked updating vaults
installed from `main` after `cad7953` (#35) and showing version `3.0.2`
([#73](https://github.com/avenoxai/avenoxbeyin/issues/73)).

The old validator allowed only a single skill path in the package manifest.
Because the V3.1.0 and V3.2.0 packages carry six paths, the new updater was
rejected before it could even be loaded. The new package keeps the old
manifest format; the other stock skill signatures stay inside the installer,
whose file hash is verified. Customized skills and managed-file conflicts are
preserved.

## Update

Run `python3 beyin.py update` inside the vault. On Windows use `py -3`.
There is no need to edit the installed updater or the version stamp by hand.
For those who wanted to move to the existing V3.2.0 package before this
release, a
[recovery path with a verified package](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/UPDATE.md#invalid-legacy-skill-hashes-73)
is documented.

## Verification

Besides the published V3.0.2/V3.1.0 packages, the release gate also tests the
intermediate install built from the real
`cad7953d6eccea96db0096279b259a14c441e728` sources. On six OS/Python
combinations, the same candidate ZIP is checked for update, read-only check,
rollback, recovery from interruption and preservation of user notes. Installing
the stock skills in two roots, from three old releases and without a state
manifest, and preserving user edits as conflicts are separate regression tests.

Thanks to @giraybatiturk for the detailed report and independent diagnosis of the bug.
