# AvenoxBeyin V3.11.0

The 60 PRs that landed on main after 3.10.0 are collected in this release; 54 of them are from contributors, and 46 arrived through the combined rounds #327 and #360. The most visible changes are Kiro support, an optional context mode that does not resend the same note in the same session, a yakala (capture) window on Windows that records what is on screen, a scheduled health check, and folders whose names signal sensitivity staying out of the index. `--uninstall` no longer deletes user text added later to managed files.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. For a fresh install, download `beyin-v3-3.11.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

**If you use Yakala** (on any operating system), run `python3 beyin.py yakala kur` once after updating (`py -3` on Windows; if you installed only the template and skill, add `--kisayol-yok` (no shortcut)). The update does not refresh the copies that `kur` writes: the `beyin-yakala` skill gets the untrusted-content rules (#302), the Linux shortcut gets the font check (#356), and the Windows listener gets the single-window protocol (#367) only this way. Until then, the old Windows listener keeps opening the window through the old path. Your key and inbox choice are preserved. If you use Obsidian Web Clipper, import the `beyne-at-web-clipper.json` file that `kur` rewrote into the extension once more; card names switch to the CLI format only this way (#296).

**The update gives a `Hook tanimi degisti` ("hook definition changed") warning:** `MultiEdit` and `NotebookEdit` were added to the PostToolUse matcher of Claude and Codex (#212). If you use Codex, complete the `/hooks` review and open a new session. The update also adds the Kiro hook to the vault; if you use Kiro, review it in the Agent Hooks panel or with `/hooks` in the CLI.

**If you sync the vault with git**, add four lines to the recommended `.gitignore`: `.kiro/hooks/beyin-v3.json`, `.kiro/skills/beyin/`, `.kiro/skills/beyin-doktor/`, `.kiro/skills/beyin-guncelle/`. These files carry machine paths; if the copy from the machine that updated first moves to the other, the reinstall there stops with a conflict.

Nothing needs to be done by hand for the Beyin block in `AGENTS.md` and `CLAUDE.md`: `update` finds the block by its markers and replaces it with the new one, and does not touch text outside the block (#362, #376).

## What's new

### Context and search

- **No repeats within a session (#364, #377):** with `python3 beyin.py preferences --context-dedupe on` (off by default) on, the `context_mode: turn` hook does not resend note windows it already gave earlier in the same session and that have not changed on disk; the last receipt that follows the notes is also given once per session, and comes back when a new receipt is written. Another section of a long note counts as new, the budget of held-back records is left to the new records, and a prompt where everything is a repeat does not clear the continuity anchor. The ledger is reset on compaction (`PreCompact`, `SessionStart` with `source: compact`) and on `SessionEnd`; in clients that do not send a compaction event (Gemini, Antigravity, Hermes), it lives at most 24 hours. The setting and the ledger are in the runtime folder (`context-dedupe.json`, `session-delivery/`); the session ID itself is not written. When it is off, the hook output is byte for byte the same. In a temporary vault, a second turn that brings a new record went from 1,346 characters to 795 characters.
- **Search does not drop when sync is late (#365):** if the source sync does not finish in 1.5 seconds, the per-turn search is no longer skipped; the context is built from the previous index with a line saying so. If the first index does not exist yet, only the waiting note is given, as before. When a large rewrite keeps the index locked, the hook prints the waiting note without exceeding the client's time limit and does not write `hook-error.json`.
- **Search fixes (#305, #357, #359):** a single-term strict search no longer returns empty unconditionally. A note whose name, title or alias appears exactly in the question ranks ahead of MOC or archive notes that mention its name often. Short numeric replies such as `1-2-3`, `2.` given to a numbered option do not bring an unrelated note in strict context; numbers of three or more digits, years, and identifiers such as `722b4dd` are preserved.
- **Exclusions on every path (#348, #315, #347):** `strict_exclude` in `retrieval.json` is also applied on the note-level fallback path used when passage search errors. In the Jev `auto_context` pool, strict candidates are evaluated first, and `strict_exclude` is applied to loose candidates too. `doctor` lists notes in archive folders that count as current because they carry no `status`, and shows the `status: archived` or `--index-exclude-dir` route.

### Rules and companion

- **A long `Kurallar.md` no longer loses its head (#379):** a `Kurallar.md` over about 40,000 characters was cut from the beginning in the source snapshot; the summary at the start of the file did not appear at startup, and the `rules X-Y (n of N)` marker counted from the truncated text. Now a file shorter than its share leaves the remainder to the long file, a `Kurallar.md` over the upper limit is kept with its head and tail, and the numbers are computed from the whole file. In the new `companion_rules_opening` field, `doctor` tells how many characters of the rule text the opening shows in full at most; `--human` writes a single line if rules are being trimmed. The overflow loop that held SessionStart for 1.7 seconds on a 270,000-character file dropped to a few passes.
- **Project rules in their own file (#376, #333):** the install block, the `beyin` skill and the `CLAUDE.md` template have you choose the target before saving a correction: a rule belonging to a single project or area goes to `projects/<project>/Kurallar.md`, and in the global `Kurallar.md` at most a single-line pointer tagged `[kapsam: <project>]` (scope) remains. The tag's syntax (`[kapsam: ...]` or `[scope: ...]`, multiple names separated by commas, `genel` and `global`) is written in the skill. When an active `project` arrives in the hook input, tagged rules of other projects are filtered out and the project file under `projects/`, `Projeler/` or `projeler/` is added. Because Claude Code does not send this field, tagged rules there keep entering the startup and the project file does not arrive automatically.
- **Startup base shares (#329):** Threads and Core also got a base share, and Last-Session's base went down from 0.20 to 0.15 (Kurallar 0.40, Last-Session 0.15, Threads 0.12, Core 0.08). The total of the bases stays at 0.75; at least 25 percent is left for Soul, Journal and the other sources, which have no base.
- **Decision ledger and dates written out in words (#324, #313):** `companion-compact` appends the decision lines (`**Karar:**`, `**Karar (Ad):**`, `**Decision:**`) in cards it moves to the archive to `Kararlar.md` in the companion folder, together with the card title and archive path. This file enters search and context and is closed to the remote advisor; no decision is copied from a private, untrusted or rejected source. The report gives `decisions_added` (`decisions_planned` in `--dry-run`). Dates written in words such as `12 Ekim 2026`, `12 October 2026` and `4→5 Ekim 2026` also count as the record date; in vaults with Turkish headings, Last-Session and Threads can now be archived.
- **Person notes (#314):** the `beyin` skill describes one note per person (`notes/kisiler/<first-last>.md`, `kind: person`, variant spellings in the `aliases` field). What the user says goes in the "Beyan" (declaration) section, and the agent's guess in the "Çıkarım (onay bekliyor)" (inference, awaiting approval) section; sensitive information such as health, political opinion and finances is not written. For creating a note by hand in Obsidian, the `📋 Templates/Kisi.md` template is added once if absent and belongs to the user. The search code did not change: a question asked by name, alias or organization brings the card.

### Receipt and session scope

- **Turns the person did not write (#378):** `<task-notification>`, a message from another agent session, and the fork Codex Desktop opens for next-message suggestions count as synthetic. The event stays in the queue with a `synthetic` marker but does not open a checkpoint and does not reopen a session closed with a receipt; no note context or Jev request goes to the suggestion fork. The missing-receipt warning at startup appears only if there are missing ones in the last 7 days, and with a count; the all-time count stays in `doctor` as `potential_missing_receipts`. Fork checkpoints recorded before the fix remain in the all-time count.
- **Edit detection (#370, #327):** in Claude Code, `beyin.py note-create`, `task-create` and `task-update` run via Bash open that session's edit window (`CLAUDE_CODE_SESSION_ID`); the receipt reminder at Stop sees these too. PostToolUse also recognizes `MultiEdit` and `NotebookEdit`, and sessions where no prompt ever arrived do not count as missing a receipt. Raw shell edits done with `sed`, heredoc or a script are still not seen (#212 open).
- **Past sessions (#332):** the edit times of sessions before the update are backfilled once from `hook-done` records; old sessions do not produce false missing receipts. Under `receipt_coverage`, `doctor` counts sessions with no observed edit separately as `no_observed_edit`.
- **Learning reminder (#369):** merely mentioning an old, unchanged knowledge note in a receipt no longer silences the learning reminder at Stop; a note written or changed in the edit window is needed. No false reminder appears in a turn where the note was written first and the receipt after.
- **External link in a receipt (#322):** `python3 beyin.py receipt ... --link URL` (`links` in JSON, repeatable, at most 20) records an outcome outside the vault such as an opened PR or a published page; `recap` shows the `links` field in each record. A link is not a source, is not read and does not take the place of `--ref`. Only `http`/`https`; an address containing user info or a known secret pattern is rejected.
- **Receipt view conflict (#325, #335):** a hand-modified `daily/v3/` or `knowledge/v3/outcomes.md` no longer stops sound notes from entering the context and new receipts from being written; `sync` warns with `degraded`. `python3 beyin.py sync --recover-views` writes the conflicting bytes to the `.archive/` folder next to the view and regenerates the view from receipts. A view whose heading was deleted is not mistaken for an ordinary note and indexed; receipt summaries from private or untrusted sources do not return to the context by this route.

### Privacy

- **Sensitively named folders do not enter the index (#303):** folders, and their subfolders, whose name contains a word signaling sensitivity such as `Kasa` (safe), `Şifreler` (passwords), `Müşteriler` (customers), `Özel` (private) or `Private` are not taken into the memory scan; Turkish letters, upper/lower case, a leading emoji or number do not matter. Records left over from the old index and receipt summaries tied to these sources drop out of the automatic context without waiting for sync. Files are not deleted or modified.
- **Frontmatter of a note with a BOM (#337):** in a Markdown file saved with a UTF-8 BOM, the frontmatter was ignored, so a note's `visibility: private` field was not read and the note was indexed as `internal`. Now the frontmatter is read; JSON settings files with a BOM also no longer error.

### Yakala

- **The on-screen source on Windows (#367, #309):** the shortcut reads the address bar of Chrome, Edge, Brave and Vivaldi; a draft typed but not confirmed with Enter does not count as an address. If the mouse is over a link, that link is the default. Selection keys: `Alt+I` the link under the cursor, `Alt+S` the open page, `Alt+P` the clipboard link, `Alt+M` text, `Alt+G` clipboard image, `Alt+W` window image. If there is no link, an image of the window is taken first with Windows.Graphics.Capture, otherwise with PrintWindow, and offered with its preview, but not added automatically: the front window could be a chat or a password manager. Because Opera Air does not give an address, an image is offered there.
- **Clipboard freshness (#367):** the freshness of clipboard content is measured not by the clock but by the clipboard sequence number. Content copied after the last successful save comes ready, and content of unknown age stays as an unchecked option; this replaces the "last 10 minutes" rule of 3.10.0. Cancelling with Esc does not consume the clipboard. A card to which clipboard text, an image or a file is added (an existing URL card too) becomes `private`.
- **Single window, fast open (#310, #307, #367):** the listener keeps a ready window in the background; when you press the key it opens without waiting for a new Python process. Pressing the shortcut again does not open a new window; it brings the open window to the front, keeping the text you typed and the selection. Esc closes on a single press, there is a visible Close button, and the frameless window can be dragged from an empty spot.
- **Link identity, on all systems (#367):** different address forms of the same YouTube video (`youtu.be`, `watch?v=`, `shorts/`, `live/`, `embed/`, `music.youtube.com`) and the same X post are gathered into one card; the domain name matches exactly. A non-default port and `#/`, `#!` redirects count as separate pages. On Windows, `isle` (process) helpers are closed with their process tree on timeout, and a write error on one card does not stop the rest of the queue.
- **Linux Wayland (#356, #366):** if `wl-paste` is missing, `yakala kur`, `yakala durum` and the empty window say `wl-clipboard` is required. If Tk sees only the `fixed` font (Turkish letters look like escape sequences), the shortcut opens the window with `/usr/bin/python3`, which has fonts; this is not used if that Python is older than 3.11. If only a PNG is on the clipboard, its small preview appears but is not added; with `Tab` or a click, the PNG is saved as a file card (at most 64 MB). X11 clipboard images are not supported.
- **Whisper (#312, #320):** if `yt-dlp` knows the spoken language, it is passed to Whisper as `--language`; the model is chosen with the `BEYIN_WHISPER_MODEL` environment variable (e.g. `large-v3-turbo`). If `whisper-ctranslate2` cannot load a CUDA library on a machine with an NVIDIA card (e.g. `cublas64_12.dll`), the audio is transcribed once more on the CPU. If Whisper produces no text, the card carries Whisper's own error line instead of "bulunamadı" (not found).
- **Source safety (#302):** only `http`/`https` addresses are processed; inputs that look like options, `file://`, local and private IPs, and addresses with user info are rejected. DNS answers are checked before Defuddle and `yt-dlp` start, and redirects on the Python HTTP path are checked too. The `## Dosyalar` (files) links of a card cannot make something outside the vault be read (UNC, drive letters, `..`, Windows device names, symlinks and junctions pointing outside). New raw records are written as untrusted data with file-specific random boundary markers. A single link coming from the clipboard now becomes a URL card, not text. There is no network isolation for the external helpers' own redirects and for DNS rebinding (#299 open).
- **Web Clipper card names (#296):** the template produces the card name in the same kebab format as the CLI (no spaces or apostrophes). You need to import the new template (see above).

### New commands

- **Scheduled health check (#290):** `python3 beyin.py scheduled-check [--notify]` runs `sync` and then `doctor` for an operating system scheduler you set up yourself; it installs no service, makes no model call, and repairs nothing. A result that needs attention is announced once as a single line at the start of the next agent session. `--notify` (off by default) also shows an operating system notification (Windows PowerShell 5.1 toast, macOS `osascript`, Linux `notify-send`); the notification arrives only when the status changes and, if the problem persists, once every seven days, and contains no note name or path. Exit codes: 0 healthy, 4 attention, 1 check could not complete, 3 another run is in progress. `doctor` shows the last run in the `scheduled_check` field. Task Scheduler, LaunchAgent and systemd examples are in `docs/v3/PREFERENCES.md`.
- **Digest report (#328):** `python3 beyin.py triage` (JSON with `--json`) lists the sources waiting in the inbox (excluding processed yakala cards), open tasks untouched for `--stale-days` (default 14) days, the knowledge notes of the last `--digest-days` (default 7) days, and the companion summary. It is read-only, makes no model call; sensitive, private and non-indexed sources do not enter the report.
- **Optional capture server (#334):** `python3 beyin.py ingest-server` (default `127.0.0.1:8484`) writes notes coming from outside sources such as a phone shortcut into the inbox as timestamped Markdown; it serves no file from the vault (`GET /health`, `POST /ingest`, `POST /yakala`). To listen on the local network, `--token` (or `BEYIN_INGEST_TOKEN`) is required along with `--host`; the token is accepted only in the `Authorization` header. Incoming notes carry `untrusted: true` and are indexed as an untrusted source; the request is limited to 1 MB. In tokenless local mode, writes with an Origin coming from a browser are rejected. Details: `docs/v3/INGEST-SERVER.md`.
- **Project scopes (#321, #339):** a folder in `.beyin-projects.json` that cannot be found no longer breaks all `--project` commands and session start; it gives a warning, `doctor` shows missing, duplicate or invalid entries under `project_scopes`, and with a missing folder sets the status to `needs_attention`. Management: `python3 beyin.py project-scope list`, `add --folder ... --project ...`, `remove --folder ...`, `prune`. `prune` also cleans paths that go outside the vault or are invalid.
- **Hook path reconciliation (#297, #355):** an explicit command for hook paths that stay stale in a moved vault or one synced from another machine: `python3 beyin.py hook-reconcile` (or `install_v3.py --reconcile-hooks`). It does not run on its own; it adapts only Beyin's hook commands to this machine, does not touch other hooks, and backs up the file it changes. When `doctor` sees a stale path, it suggests the command. After reconciliation, `--uninstall` no longer gives a false conflict.

### Clients

- **Kiro (#344):** Kiro IDE 1.x and Kiro CLI V3 connect to the same engine at the project level in the vault. Install and update write `.kiro/hooks/beyin-v3.json` (SessionStart, UserPromptSubmit, PostToolUse for `write` tools, Stop) and the three startup skills under `.kiro/skills/`; Kiro reads `AGENTS.md` directly. `context` and `receipt` accept `--harness kiro`, and `doctor` and `hook-reconcile` also check Kiro hook paths. `SessionEnd` is not connected because it exists only in the CLI, Kiro has no `PreCompact`, and edits made with a shell command do not trigger PostToolUse. If you do not use Kiro, you can silence the hook file with `python3 beyin.py preferences --exclude-component adapters/kiro` (applied at the next install or update). Details: `docs/v3/KIRO.md`.
- **Hermes (#351, #352):** A2A (`a2a`) sessions count as unattended by default; no receipt is expected and no missing receipts accumulate. If you use Hermes as a personal assistant in a channel such as Slack, count the channel as attended: `python3 beyin.py preferences --hermes-attended-platform slack`. The opposite direction is `--hermes-unattended-platform <name>`, and returning to the default is `--hermes-reset-platforms`. The setting is in `hermes-platforms.json` in the runtime folder.

### Sync and multiple devices

- **Conflict copies from the sync service (#291, #331):** copies bearing the service's stamp (`(... conflicted copy ...)`, `(Case Conflict)`, `.sync-conflict-...` and Turkish-localized names) do not enter the index and make `sync` `degraded`. Numbered names such as `Not 2.md`, `Not (1).md`, while the original note exists in the same folder, are listed only under `sync_copy_candidates`, with whether their contents are identical, and stay in the index. Copies inside `receipts/` are not indexed and give a warning. No file is moved, deleted or renamed. If the stored sync stamp ends up in the future (such as after a state restore), a warning appears.
- **State pin from another machine (#292, #319):** a default state path coming from another operating system or another user account (`AppData/Local/beyin-v3/...`, `.local/state/beyin-v3/...`, `Library/Application Support/beyin-v3/...`) falls back to this machine's default in the CLI and lifecycle hooks; a custom `--state` and MSIX paths are preserved. When a fallback happens, each command writes a single line to stderr; stdout and `--json` do not change.
- **Cross-device session awareness (#298):** with `preferences --parallel-sessions on`, sessions are also visible on other devices through `.presence/` files at the vault root. `SessionEnd` deletes the file, records older than 45 minutes are dropped, and the file is written at most once every 5 minutes. The random device ID stays in `parallel-presence-device.json` in state; do not sync this file with the vault.
- **Hook records do not pile up (#306, #341):** `state/hook-done/` markers older than 7 days are moved, after a successful queue drain, to the `hook_done_ledger` table in `memory.sqlite3` (only the event hash, client and event name); `doctor` counts both together. The SQLite size is not limited. On Windows, a marker locked by another process is left to the next round, and cleanup does not stop.
- **Bridge on an old-schema database (#293):** in a database coming from v3.8.0 and earlier that has not yet migrated, the global bridge's project context (tasks included) no longer silently drops.

### Install, update and Windows

- **`--uninstall` does not delete user text (#380):** if text was added later to the `AGENTS.md` the install created and a reinstall or `update` was done, removal deleted the file together with the text; the `AGENTS.md`, `CLAUDE.md`, `.claude/settings.local.json`, hook JSONs and `.codex/config.toml` that existed before the install were restored to their old state. Now only the Beyin block, the V3 hook entries and the `hooks = true` line under `[features]` are removed; a file the install created is deleted only if nothing else is left in it. Preserved files are listed in the output under `kept_user_text`. The fix applies only to removal with this release's installer.
- **Instruction block as single-line paragraphs (#362):** the `AGENTS.md` block, the `beyin` skill and the `CLAUDE.md` template moved to single-line paragraphs instead of hand-wrapped lines; the text is the same.
- **A hook input with a BOM on Windows (#345):** the UTF-8 BOM that Windows PowerShell 5.1 adds to hook and CLI stdin led to a `JSONDecodeError` and silently dropped that turn's context; it is now accepted.
- **Small fixes (#330, #301):** `task-create` fills in `created_at` and `updated_at` if not given, and preserves valid dates that are given. `doctor` warnings show full GitHub addresses instead of `docs/...` paths that are not in the package.

## Rollback notes

- 3.10.0 does not know within-session repeat prevention; `context-dedupe.json` and `session-delivery/` are ignored, and full context is given on every prompt. This path was tried: update from 3.10.0, turn the setting on, rollback; `doctor` exited with 0, SessionStart and UserPromptSubmit gave normal context, and `hook-error.json` was not created (#364).
- 3.10.0 does not use the `synthetic` field in the queue and `recent_missing_receipts` in `hook-health.json` (#378); on going back, the startup warning again looks at the all-time count.
- 3.10.0 scans sensitively named folders again; notes inside them that do not carry `visibility: private` may enter the automatic context (#303).
- `hermes-platforms.json` does not break the old release's preference schema; 3.10.0 does not read the file and uses its own fixed list, which does not have `a2a` (#351, #352).
- The runtime files of `scheduled-check` do not break the return, but 3.10.0 has no such command: the scheduler task returns 2 (usage error). Turn off the task before going back.
- Rollback removes the managed Kiro files that the update added (#344). `📋 Templates/Kisi.md` belongs to the user; its customization is preserved after update and rollback (#314).
- After rollback, `--uninstall` with the 3.10.0 installer gives a conflict and stops on a file to which user text was added later, deleting no data (tried in #380). If you run an old installer directly on top of the new install and remove with it, the old behavior continues.
- The `doctor` of 3.10.0 counts only files in the `hook-done/` folder and does not read the `hook_done_ledger` table (#306). Events older than 7 days moved to the table in this release do not appear on going back in the `acknowledged_events` count and the client observation list; the data is not lost.
- The `.presence/` folder created at the vault root with `--parallel-sessions on` is not used by 3.10.0; since it does not scan folders starting with a dot, it does not enter the index either. You can delete it by hand if you like (#298).
- The new read-only `doctor` fields (`companion_rules_opening`, `scheduled_check`, `project_scopes`) write no files; they leave nothing to clean up on going back.

## Verification

- Before release, 1,793 V3 tests passed on Python 3.11 and 3.14; the 10/10 development and 6/6 holdout semantic scenarios passed (synthetic, offline measurement). The CI package verifies on Windows, macOS and Linux with Python 3.11 and 3.13.
- The package was verified on the real 3.10.0-to-3.11.0 update path: clean install, update from the published release, read-only check, no-op on the same release, rollback, recovery of an interrupted update and preservation of user notes. Temporary vaults installed with 3.10.0 were updated with `update --package`; on a plain install, in a vault with user text outside the block, and in a CRLF vault, a single block remained, and the user text and `Kurallar.md` were preserved (#362, #376). Update and rollback were tried with repeat prevention on (#364) and with text added to `AGENTS.md` (#380); in both, `doctor` came out clean and SessionStart gave normal context. Context from the previous index on a sync delay was verified on the UserPromptSubmit and SessionStart paths for Claude and Codex in an installed test vault (#365).
- On a real desktop: on Windows 11, by a contributor, the link of the page open in Chrome, the video under the cursor on the YouTube home page, a WGC image of a Blender window, an image instead of a link in Opera Air, Esc closing on a single press and a single window on a fast double shortcut (#367); a `scheduled-check --notify` notification from the Windows 11 Task Scheduler (#290); on CachyOS KDE Plasma 6 Wayland, the selected and unselected states of the PNG option (#366) and the handoff to the system Python (#356, with a temporary fix equivalent to the PR code).
- Not tried in a real environment: delivery in the Kiro client (the hook schema was compared with Kiro's official documentation), the CUDA-to-CPU switch on NVIDIA hardware, the `scheduled-check` notification on macOS and Linux, writing the PNG card to disk on Wayland, and images of protected, fullscreen or HDR windows. Opening an issue is enough for feedback.
