# AvenoxBeyin V3.3.0

Claude Code now sees the rules in your `AGENTS.md` after install as well (#84). This release also adds OMP (Oh My Pi) support as the sixth client, and an option to keep your customized old V2 runner alongside V3.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. After updating, open a new client session. The existing clients' managed hook definition files did not change in this range; updating from a V3.2.1 install reports `trust_review_required: false`. The update adds the `.omp/hooks/pre/beyin-v3.ts` file to the vault for OMP; if you do not use OMP, this file has no effect. For a fresh install, download `beyin-v3-3.3.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

## What's new

### Claude Code and AGENTS.md (#84)

Claude Code does not read `AGENTS.md` by default if a `CLAUDE.md` exists in the same folder. In earlier releases, when there was no `CLAUDE.md`, install created it with only the Beyin block. As a result, your own rules in `AGENTS.md` were silently dropped from Claude sessions. If `CLAUDE.md` already imported `@AGENTS.md`, the block was loaded twice.

- If there is no `CLAUDE.md`, it is now created with only an `@AGENTS.md` line. The block arrives once, through `AGENTS.md`. The import also works in Claude Code sessions that cannot read `AGENTS.md` directly.
- If `CLAUDE.md` imports `AGENTS.md`, the block is not written there. A block left over from a previous install is removed on update.
- An existing `CLAUDE.md` that does not import behaves the same as before: the block is written there.
- A `CLAUDE.md` and `AGENTS.md` that are symlinks to each other count as a single file.
- A `CLAUDE.md` created by an earlier install and consisting only of the block is automatically turned into an `@AGENTS.md` line on update. If you added your own text to this file, the block stays in place. To make your rules show up in Claude, add an `@AGENTS.md` line at the very top of the file; the next update removes the block and keeps your text.
- `uninstall` deletes the `CLAUDE.md` that the install created. A `CLAUDE.md` whose block was removed is restored to its pre-install state.

### OMP (Oh My Pi) support (#85)

- OMP is the sixth supported client, after Codex, Claude Code, Antigravity, Hermes and OpenCode. Install writes a single managed file to the vault: `.omp/hooks/pre/beyin-v3.ts`. There is no connect or enable step; just open OMP in the vault folder.
- The hook runs only in sessions whose working folder is the vault. The two paths are compared after resolving symlinks, including the `/private` difference on macOS. Task sub-agent sessions are skipped.
- Do not copy the hook into the global `~/.omp/agent/hooks/pre/` folder; it adds nothing. Details: [OMP guide](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/OMP.md).

### Keeping a customized legacy runner (#77)

- To leave a V2 runner you customized (for example `.claude/scripts/flush.py` or `.claude/hooks/session-end.sh`) running alongside V3 instead of turning it into a stub, use `--keep-customized-legacy <path>` at install. The installer does not touch the kept runner or the hook line that calls it by its full path. Editing or deleting the line does not stop later updates. The decision is stored; you do not need to pass the flag again on later updates.
- To end the keep decision, use `--accept-customized-legacy <path>`; the runner is retired and drops off the list. A path that does not exist or is already retired is rejected.
- The kept runner runs side by side with the V3 hook; this is your choice. Details: [migration guide](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/MIGRATION.md).

## Verification

- 419 V3 tests and the unchanged frozen retrieval gate (development 10/10, holdout 6/6) run before release. The release pipeline verifies the same ZIP on Windows, macOS and Linux with Python 3.11 and 3.13: clean install, migration from the published V3.0.2 and V3.1.0 packages and from the `cad7953` install, no-op, read-only, rollback, recovery of an interrupted operation, and preservation of user notes.
- Before release, updating to this release was tried on synthetic vaults installed with the published V3.2.1 package: with no `CLAUDE.md`, with a `CLAUDE.md` that imports `AGENTS.md`, and with user text added to the file the install created. `rollback` returned to V3.2.1 and the notes were preserved.
- Marker test with Claude Code 2.1.280: a rule placed in `AGENTS.md` did not show up in the Claude session on a V3.2.1 install; after the same vault was updated to V3.3.0, it appeared together with the Beyin block.
- The OMP hook tests run under Bun with a fake OMP object and passed locally on Bun 1.3.14. They are skipped in CI because Bun is not installed there yet. No live OMP session test was run for this release; the event mapping was verified against the local OMP 18 sources.
