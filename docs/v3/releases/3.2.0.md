# AvenoxBeyin V3.2.0

Better source continuity and alias search even with Jev off, optional sourced memory evaluation (`jev-memory`), and an optional global bridge for selected projects outside the vault.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. After updating, open a new client session. The managed hook definition files did not change in this range; the update reports `trust_review_required: false`, and in the normal flow no client trust review is expected. If you add the global bridge yourself, you need to complete the client's trust review for that separate hook definition. For a fresh install, download `beyin-v3-3.2.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

## What's new

### What you get even with Jev off

- Source continuity: up to three sources the hook actually delivered are remembered for short follow-ups such as "test that too" in the same client and session. No raw message or transcript is stored; only the source ID, hash, revision, project and time are kept. The window expires 20 minutes after a concrete topic; vague follow-ups do not extend it. The source is not carried over on a different project, a new topic, a source change or loss of permission. Topic separation is a limited set of Turkish/English word rules, not a guarantee of general language understanding.
- Alias search: `aliases: ["ses ofseti", "audio offset"]` in a source's frontmatter widens local candidate search. It does not bypass the visibility, trust, freshness and supersede gates.
- Delivery packing was rewritten. A selected source is not cut in the middle of its envelope, the top-level `omitted_count` and `truncated` information is preserved through to the final output, and a record with oversized metadata cannot consume a source slot.
- A checkpoint record carries a bounded project label and a hash of the project path; `project` and `project_id` appear in the `receipt-gaps.json.checkpoints` field of `doctor --json`. The schema migration is additive; old rows are preserved.

### Optional Jev (off by default)

- New `jev-memory` command: `python3 beyin.py jev-memory --project PROJECT --file proposal.json --json`. It uses the existing `review` feature and accepts the same proposal format as `jev-review`. In a single request it asks questions about support, certainty/intent and knowledge type, plus one relationship question per optional `prior_record_ids` entry (up to four prior records). The result is always advisory: `approved`, `memory_written`, `task_created` and `task_completed` always stay `false`; the agent still does the writing. Low confidence, an unsupported claim, an uncertain statement or a contradiction with a prior record returns `route: inspect_sources`.
- `remote_allowed: false` or `sensitivity: sensitive` metadata prevents the record, title included, from being sent to Jev. These records are still used locally and are packed alternately with the ones selected remotely. For `remote_allowed`, write a JSON/YAML boolean, not text.
- `context --jev` now selects from up to 16 candidates of the local search and can take a relevant candidate that did not fit in the first local output. Up to three sub-requests separated by semicolons are evaluated separately. The record count and character budget in the final output did not change. If the local candidate search never finds a record, Jev cannot find it either.
- When automatic context (`auto_context`) is on, local search produces up to 16 loose candidates, the two groups are merged alternately, and up to 8 records permitted for remote evaluation are selected. Local-only records do not consume the remote candidate quota. This feature still requires a separate, explicit opt-in.
- `jev-answer` and `jev-review` now send the source's full index text and bounded scope metadata, instead of a window of 400 characters on each side of the quote. If the full context does not fit within the 4,000-character per-claim limit, the text is not truncated: the claim returns to local review as `uncertain` with `source_context_incomplete`.
- The `jev status` and `doctor` counters were expanded: `key_checked`, `network_requests` and `p95_latency_ms` were added, and the median calculation was fixed. Local log lines pass through a fixed field list; no query, source text or key is written.

### Optional bridge for projects outside the vault

- The bundled `.claude/scripts/beyin_v3_bridge.py` connects Claude Code and Codex sessions opened in the project roots you choose to the second brain's existing queue. `--print-config` only prints JSON; you add the generated hook groups to `~/.claude/settings.json` or `$CODEX_HOME/hooks.json` yourself. Install and update do not touch global settings.
- Only `SessionStart`, `Stop`, `PreCompact` and `SessionEnd` are forwarded; `UserPromptSubmit` and `PostToolUse` are never forwarded. `--project-root` can be repeated, and `--context-chars` is a separate startup budget between 0 and 4000 (default 1500). The vault, its subfolders and other vaults that have their own `.beyin-runtime.json` file are skipped.
- With the bridge on, only the project label, the receipt session ID, the absolute CLI path and a sourced-recording instruction are given at startup. The Companion, Last-Session, old receipts or personal note bodies are not automatically carried into the external project. Steps: [GLOBAL-BRIDGE.md](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/GLOBAL-BRIDGE.md).

## Privacy

Jev is off by default and a clean install ships with `off`; the update preserves a saved `off`/`shadow`/`on` preference. While it is off there is no network, key or cache access; the continuity and alias improvements above still work. When it is on, `context --jev` sends the query, the title (160 characters), text excerpt (800 characters) and project/status/date information of permitted candidates to the provider; with automatic context on, the prompt plus the title and first 600 characters of up to eight candidates are sent; `jev-memory`, `jev-review` and `jev-answer` send the full source text of permitted evidence. Records with `private` visibility, `remote_allowed: false` and `sensitivity: sensitive` are never sent by any path. The key is read from the `TYPESAFE_API_KEY` environment variable (or from the absolute-path `env_file` in `jev.json`); it is not written to a note, to version control or to a command argument. The global bridge does not require a Jev call, an API key, a new daemon or a global startup update check.

## Verification

The release pipeline builds the ZIP once. The same package is tested on Windows, macOS and Linux with Python 3.11 and 3.13: clean install, migration from the published V3.0.2 and V3.1.0 packages, no-op, read-only, rollback, recovery of an interrupted operation, and preservation of user notes. With this release the V3.1.0 migration was also added to the release gate. 387 V3 tests (12 of them new bridge tests, 34 new decision-quality tests) and the 16 cases of the unchanged frozen retrieval gate run before release. The installed-package check verifies that the saved Jev preference is preserved, that a clean install comes up `off`, and that no call to the provider is ever made.

The new delivery measurement runs three times each on a frozen synthetic corpus of 18 conversation turns and 8 manual cases, in two candidate orders. The transport is a **label-driven ideal selector**, not live Jev. The repetitions are not independent samples; this corpus is development/regression data, not an unseen holdout.

| Runtime/mode | Turn required-source hits | Turn extra sources | Manual required-source hits | Manual extra sources |
| --- | --- | --- | --- | --- |
| V3.1.0 off / shadow | 60/90 | 18 | 30/42 | 42 |
| V3.1.0 on, ideal selector | 72/90 | 0 | 30/42 | 42 |
| This release off / shadow | 90/90 | 6 | 42/42 | 42 |
| This release on, ideal selector | 90/90 | 0 | 42/42 | 0 |

With continuity removed, the turn hits in off mode drop back to 60/90, and with aliases removed, the manual hits drop back to 30/42. So the measured recall gain is a local code gain, not a demonstrated Jev gain. Manual local precision stays at 0.50 in off mode and the extra sources remain. The ideal selector proves only the selection and delivery pipeline, not model intelligence.

No live provider regression or real Desktop cold-session test was run for this release. A CLI hook simulation is not proof of real Desktop hook delivery; after installing the bridge, open a new session in each client and separately verify with `doctor` that the event was seen. Detailed evidence and limits: [PR 69 review document](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/decision-quality/REVIEW.md) and the [bridge guide](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/GLOBAL-BRIDGE.md).

## Rollback note

Before you `rollback` or `uninstall` to an older release that does not include the bridge, remove the bridge handlers you added to global settings. Leaving a nonexistent script in a global hook produces a client error. When removing, delete only the bridge handlers and keep your other hooks.
