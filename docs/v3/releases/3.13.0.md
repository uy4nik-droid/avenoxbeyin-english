# AvenoxBeyin V3.13.0

The contributions since 3.12.0 and the fixes of the 12 November maintenance round are collected in this release. Yakala (capture) cards can optionally be handed off to a Claude Code or Codex agent; bulk sending requires a preview, and music recognition requires a separate permission per job. The Pi client and the OpenCode global bridge arrived; an optional local web view, workspace commands and a read-only `beyin-kontrol` (check) skill were added. The startup context now reserves all rules, the status of open topics and the newest handoff card first; Turkish search recognizes new inflection and vowel-drop forms, and the local index no longer grows without limit. New tools are off by default or run only when explicitly invoked.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. For a fresh install, download `beyin-v3-3.13.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

**If you use Yakala**, run `python3 beyin.py yakala kur` once after updating (`py -3` on Windows; if you use only the template and skill, add `--kisayol-yok` (no shortcut)). `kur` refreshes the separately copied listener/window script and the `beyin-yakala` skill; the update does not reinstall these copies. Your shortcut and inbox choice are preserved. Agent mode is not turned on by this step; you choose it separately if you like (below).

**Hook definitions:** when moving from a clean 3.12.0 install to this release, the vault hook definitions do not change (`trust_review_required: false`); the Codex `/hooks` review is not needed just for this update. If you are coming from an older release, complete the trust step for the client that the update reports. The update does not produce trust approval. Open a new session in the client for the refreshed engine and skills.

**If you use the global bridge:** the update does not change the clients' global settings. So that the Claude and Codex bridge can see an edit in an outside project and remind about recording once at Stop, the bridge now also installs a separate `PostToolUse` handler. If you want this, re-run `python3 beyin.py bridge --harness claude --project-root "/full/path/MyProjects" --install` once (`--harness codex` for Codex); the reinstall removes the previous bridge handlers and writes the selected set. Keep all your previous `--project-root`, `--event` and `--context-chars` choices when reinstalling.

**If you moved the vault to another folder:** the local index is tied to the vault path it was built for. In a moved vault, `update` stops without changing any file and asks for the binding to be moved explicitly. Run the installer in the downloaded package with the new path, the old state folder and `--rebind-state`: `python3 scripts/install_v3.py --vault "/new/path/MyBrain" --state "<old state folder>" --rebind-state`. The old state path is in the `state` field of the `.beyin-runtime.json` file in the vault. Details: https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/MULTI-MACHINE.md

**Rollback:** `python3 beyin.py rollback` returns to 3.12.0. Notes, `.beyin-workspaces.json` and the new state settings are preserved; the old engine ignores them and reads Pi receipts as manual receipts. If you used Pi, before the rollback remove the `-e` path containing `--beyin-project-root` from your personal Pi settings and aliases; once the extension is deleted, Pi does not recognize this flag and will not start. If you installed the OpenCode global bridge, run `python3 beyin.py bridge --harness opencode --uninstall` before the rollback.

**If you sync the vault with git**, add the new skill copies to your machine-specific file list: `.claude/skills/beyin-kontrol/`, `.agents/skills/beyin-kontrol/`, `.kiro/skills/beyin-kontrol/`. The new `.beyin-workspaces.json`, on the other hand, is a shared record belonging to the vault and should be synced together with `.beyin-projects.json`. `doctor` now reports known install files tracked in Git as information (`tracked_machine_files`).

## What's new

### Yakala

- **Corrupt text and PDF warnings (#625, #623, #641, #642):** corrupt Unicode extraction does not stop the next cards in the queue. An invalid UTF-8 attachment is reported by name and the valid text is preserved; for a PDF whose text cannot be extracted, an explicit warning remains on the card and in the processing result. Written files are kept as valid UTF-8.
- **Save and hand to an agent (#384, optional):** off by default and requires an installed Claude Code or Codex CLI. When turned on with `python3 beyin.py yakala kur --ajan claude` (or `codex`, `otomatik` (auto)), Enter still only saves the card; **Ctrl+Enter** saves the card and starts a separate agent session for that card. The agent works inside the vault and writes the result, with source links, to memory and to the monthly agent log. The setting is kept under `state/yakala/ajan/`. This option is not available in the `kdialog`/`zenity` fallback windows on Linux; a saved card can be sent with `yakala ajan-gonder CARD_ID`.
- **Bulk sending with a preview (#414):** `yakala ajan-toplu` only previews by default; it creates no job record, uses no network, and starts no agent. To send, give the same command `--gonder --plan PLAN`. If a card, request or setting changed after the preview, the plan does not hold and sending is rejected. The returned `batch_id` means only acceptance into the queue; jobs that have not started can be rolled back.
- **Music recognition (#415, with explicit permission):** on Instagram, TikTok and YouTube cards, the page's music information can be read. Extracting a local audio sample (`--ses-isle`, at most 12 seconds) and sending the sample to AudD (`--tani-servise-gonder`) each require a separate permission per job; words in the request text, Ctrl+Enter, the general network setting or bulk sending do not grant these permissions. The AudD key is entered secretly in the terminal with `yakala ajan-muzik audd`; if there is no key, the service is off. Downloading the full song, reading accounts or cookies, and bypassing DRM are not part of this feature.
- **Word documents (#597):** `yakala isle` extracts paragraph and table text from `.docx` files without an extra package; limits are applied against zip bombs and XML entity attacks.
- **Missing-section warning (#601):** when the missing-section check detects an inconsistency, the card carries a warning; if the source cannot be verified, no completeness guarantee is given.
- **Windows and macOS (#458, #459, #481, #487, #504, #513):** files copied in Windows Explorer are captured as file cards. A crash on ready-window close, an empty read on the broker connection, and Esc pressed with a modifier key closing the window were fixed. On macOS, the transient `EIO` race in the LaunchAgent reload is retried only on a transient error. The post title is split after the matching username.
- **Source safety and card writing (#299, #486, #464):** the egress protection works together with the user's proxy setting, a corrupt URL does not stop the queue, and files outside the card folder are not read. A hand-modified `kaynak_turu` (source type) does not hand a non-YouTube address to `yt-dlp`. Concurrent card writes do not overwrite newer capture data; private links in extra addresses keep `private` visibility.

### Clients and bridges

- **Local time (#631, #630):** the startup and prompt context give the local time with its UTC offset; the session card is written from this time.
- **Bridge for a moved vault (#618, #632):** doctor reports, read-only, old vault paths left in the global bridge. Steps for reinstalling the bridge from inside the new vault after a move were documented; global settings are not changed on their own.
- **Pi (#385):** the installer writes `.pi/extensions/beyin-v3.ts` into the vault; it is enough to open Pi in the vault folder and approve project trust for the extension. Access from another project folder is enabled only with an explicit `--beyin-project-root` scope. Receipts are written as `harness: manual` and `client: pi`. It was tried with a real Pi 1.3.0 session on Linux; there is no live verification yet for Windows, macOS and the interactive interface. Details: https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/PI.md
- **OpenCode (#592):** the project root is taken from the session directory, not the server process's folder. An optional global bridge for projects outside the vault: `python3 beyin.py bridge --harness opencode --project-root "/full/path/MyProjects" --install`.
- **Recording loop in the global bridge (#505):** the Claude and Codex bridge sees a file edit in an outside project and, once per session, reminds to write first to a note and then to the receipt. On an existing bridge install, you need to re-run the `--install` command for this.
- **Shell and CLI edits (#212):** in Claude Code, when a Bash or PowerShell command modifies a vault Markdown file whose name it gives explicitly, that edit also enters the Stop reminder and the receipt scope; the same applies to notes and tasks written with `beyin.py`. The command text is not stored; paths given via variables and commands that write in the background are not seen. In Codex, shell commands are not read.
- **Claude Desktop and reminders (#566, #567, #570, #594):** the notification turns of Claude Desktop's connected sessions do not count as user turns; a `[kaydetme]` ("don't record") quoted in synthetic text does not turn off the reminder. Known edits outside the vault do not trigger the receipt reminder. An embedded receipt call preserves the caller's output encoding.
- **Bridge parser (#496, #575):** argument errors return to an embedded caller with an exit code; on Python 3.14, the bridge's program name and error output stay the same as on earlier Python versions.

### Session start and context

- **Stale rules (#624, #622):** a Kurallar.md that changed on disk and has not yet been synced is not reported as if there were no rules at all; the privacy and trust gates are preserved.
- **Rules, open topics and handoff card (#529, #528):** if space is tight at startup, the full general and project rules, the topmost dated handoff card and a short view of all open topics (status and next step) are reserved first; the remaining space goes to identity, Journal and other sources. The startup stays within the 10,000-character budget. When rules are trimmed, a memory-layout warning is added to the startup (#470), and multi-line rules are not split in the middle (#537).
- **Rule delivery (#616, #610):** having an `@path` in `CLAUDE.md` is not counted as proof that the file was actually delivered to the client. Rules at startup are not removed because of an unverified import; the repeat-prevention proposal stays open under #610.
- **Identity share (#569, #591):** when `Core.md` exists, `Soul.md` is not counted as a missing source; a vault that holds only `Soul.md` also gets an identity share.
- **Optional knowledge card (#595):** if `knowledge/INDEKS.md` exists, this hand-maintained "when to open" card is shown at startup in place of the ever-growing article list. If there is no card, nothing changes.
- **Project resolution (#456, #475, #419, #451, #496):** if the name of the working folder or one of its parent folders matches a project, the session rules are taken from that project; the `🏰 300-Projects/` layout of the official template is also recognized. A single faulty entry in `.beyin-projects.json` is skipped with a warning without loosening the boundary; other mappings keep working.
- **Stale topics (#568, #572):** `triage` reports open companion topics that have not been updated for a long time or have no date.

### Search and Jev

- **Empty candidate titles (#621, #619):** Jev candidates containing a null title are normalized without crashing the search.
- **Turkish stems (#430, #516):** verb inflections, vowel drop (ağız/ağzı, burun/burnu, oğul/oğlu) and hyphenated names reduce to the same stem; nouns such as `durum`, `verim` do not fall to a wrong stem. Turkish morphology is not considered fully supported.
- **Typo tolerance (#561):** in context search, misspelled query words match in a limited way; the visibility and eligibility gates are preserved.
- **Preserving the selected passage (#530, #508, #519, #520):** the passage selected in search is carried through to the final context envelope; if a second passage carries the question, it is added from the remaining space, and truncated text is not repacked. The privacy gates stay the same.
- **Jev candidates (#533, #518):** loose candidates are filtered before the cut and merged in section order; the envelope's index fields are not sent to the model. Jev is off by default.
- **Two optional rules for unscoped search (#532):** in `retrieval.json` in the runtime folder, `unscoped_min_shared: 2` requires a multi-word question to share at least two words with the note; `unscoped_dominant_weight` pushes down results of a project that holds more than half of the notes. Both are off by default and affect only an explicit `context` search with no `--project` given. The gain depends on the vault structure; measure with your own questions before turning them on.
- **Speed (#522, #526):** word counts per note are cached, and the note text is not split into words when there are no query terms.

### Notes, tasks and receipts

- **Evidence and an idempotency key in note writing (#443):** `note-create` and `note-edit` take an optional `idempotency_key` and `evidence_refs`. A repeated request with the same key does not write a second time; `evidence_refs` uses the same contract as task evidence (a source that exists in the vault). `expected_source_hash` is an alias for `expected_sha256`.
- **Strict task evidence (#495):** the evidence that closes a strict task must carry the task's ID. The check runs only on newly attached evidence; tasks closed with an earlier release are not considered invalid.
- **Input validation (#543, #544, #587):** text containing CESU-8 and lone surrogates is rejected with `Utf8InputError` before being written. The `note-read` result carries an `exists` field, and with `--must-exist` a missing file gives an error. A corrupt settings file is named, and error output is written with UTF-8 characters.
- **Portable names (#582):** `note-create`, `task-create` and `note-edit` creating a file reject, before writing, names that cannot be carried between Windows, macOS and Linux (device names like `CON`, `<>:"|?*`, a name ending in a dot or space, an excessively long path, another Unicode form of the same name).
- **Shared write lock (#476, #489, #527):** all human-note writers are serialized on the same lock, and replacement of the lock file is noticed. Notes in archive folders excluded from the index can be opened with `note-read` and `note-edit`.
- **Receipt identity and views (#603, #514, #517):** a difference only in line endings (CRLF/LF) does not count the same receipt as a conflict and does not stop daily generation. Daily and outcomes views are bound to the receipt by event id; for a receipt whose summary is hidden, the event id is not shown either. A way to hide receipt nodes in the Obsidian graph was documented.
- **Receipts from private sources (#525, #578, #579):** a receipt summary tied to a private, unreadable or non-indexed source stays hidden in recap and views; the private-ref gate also catches Unicode spelling differences.
- **Receipt reminders (#473, #510, #563):** checkpoints written without an observed edit are shown separately in the startup warning, the coverage notice is given once per session; knowledge-note evidence is checked for all edited paths.
- **`supersedes` (#577, #605):** ineffective `supersedes` references are shown with their source and reason in the human-readable `sync` and `doctor` output; references that form a cycle retire no note.

### Optional tools

- **Local web view (#423, #371):** `python3 beyin.py web ac` (open) shows tasks, recent receipts, the sizes of memory files and the doctor summary in the browser. It opens only on `127.0.0.1`, checks Host/Origin and CSRF on every write, and shuts down if unused for 30 minutes. Writes go through the same path as CLI commands; `--read-only` turns all of them off. Retired notes cannot be opened even from a direct record link. Install, update and hooks do not start it. Details: https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/WEB.md
- **Workspaces, link checking and MOC (#444, #445, #448):** `workspace`, `lint` and `moc` run only when explicitly invoked; SessionStart, `sync` and `doctor` do not run them. Metadata is kept in the `.beyin-workspaces.json` file; the `.beyin-projects.json` format does not change. `workspace plan` and `workspace provision --dry-run` show without writing; if `provision` errors, it rolls back only its own changes. An interrupted setup continues with the recorded name, type, source and rules; it is not silently re-planned with different options. `lint` reports broken wikilinks, missing headings and orphan notes. `moc` rewrites only the marked block and does not touch an unmarked file.
- **`beyin-kontrol` skill (#589):** compares a status written in memory against the source to see whether it is still correct. It runs only when the user asks, and writes nothing without approval.
- **Chat trace (#471, #599, optional):** `python3 beyin.py chat-trace on` turns on a hint to write a short trace for meaningful chats where no file is edited; it is off by default, no transcript is stored, and no model is called. `chat-trace backfill` is for extracting traces from old sessions that Claude Code deletes after 30 days by default: the default call is only a trial run, writing requires an explicit summary per session, and secret masking is applied. The Claude Code record format is not documented; unrecognized records are skipped.
- **Offline mutation queue (#409):** `python3 beyin.py mutation-queue --enable` opens a local queue on this machine. Note, task and receipt changes are put in the queue with `--enqueue` and applied in order with `--replay`; each result is recorded before moving to the next and reconciled after an interruption. It is off by default, and state is kept only in this machine's state folder. It is not sync across devices; that design stays open under #205.

### Local state, install and resilience

- **Incomplete scans and I/O errors (#634, #636, #637, #638, #644, #645, #649, #651):** queue replay, learning record, doctor, triage and audit do not present an unreadable or missing source as a healthy empty result. A corrupt queue record is set aside and the next valid job continues.
- **Sample text and time ordering (#639, #643, #646, #648, #650):** example statuses in code blocks do not count as live tasks, a handoff card is not cut at a sample heading, and audit compares timestamps with time zones.
- **Redirected human output (#640):** Turkish and emoji in `--human` output are preserved as UTF-8 when redirected to a file or another command.
- **Bounded event history (#585):** the local index always keeps each record's newest event; of older snapshots it keeps the newest 10 per record for 30 days. A background job cleans the excess in small pieces and deletes old temporary files. `python3 beyin.py state-compact` (use `--dry-run` first) performs the pending cleanup and runs `VACUUM`; `doctor` suggests it when needed. The vault, notes and receipts do not change; `history` no longer shows snapshots older than this window.
- **Moved vault (#593):** the installer binds a moved vault to the new path only with an explicit `--rebind-state` and first copies the index as `memory-before-rebind.sqlite3`. If the recorded old folder still uses this state, the binding is not moved. `--plan --rebind-state` shows the binding that would change without writing.
- **Companion archive (#460, #491, #536, #596):** `companion-compact` bounds the archive scan, does not rewrite the same full backup on each run, and does not duplicate archived content. In the monthly rollover, the old backup is used after re-checking the live file.
- **Install and migration (#472, #523, #539, #540, #548, #550, #552, #564):** an old runner copy retired by another machine counts as retired. `doctor` reports known install files tracked in Git; steps for safely removing machine-specific files from tracking were documented. The type of package and install manifests is verified, and path quoting in hook launchers was hardened. The installed `AGENTS.md` closing protocol asks for `note-read` / `note-edit` to be used when editing notes; outside-project install is described separately from vault memory.
- **Check frequency and hook resilience (#457, #483, #557, #558):** if the check record cannot be written (another client's lock, a read-only file, a full disk), that turn's automatic check is skipped and the warning says why; the hook keeps giving context from the previous index. `doctor` also counts sessions that ended without a prompt marker.
- **Ingest server (#485, #542, #586, #590):** a corrupt request line, a non-numeric `Content-Length` and an invalid UTF-8 body are rejected with HTTP 400; on Windows, address reuse was turned off to prevent port conflicts. Bulk ingest validates the whole list and ID conflicts before the first write.
- **Project scope flag (#607, #609):** `--shared-unscoped` is accepted only with `project-scope add`; in other calls it is rejected instead of being silently ignored.

### Privacy and the secret filter

- **Prefixed environment variables (#606, #608):** with `preferences --secret-filter on`, assignments such as `OPENAI_API_KEY=...`, `DB_PASSWORD=...` and the `export`, `set`, `$env:` forms are also masked; configuration names such as `PUBLIC_API_KEY_NAME` are not masked. The filter also catches keys split by Unicode format characters (#583). The filter is off by default and is not a complete data leak prevention tool.
- **Triage summary (#581):** `secret`, `restricted` and `untrusted` notes, and notes whose frontmatter is unreadable, do not enter the triage summary.

### Documentation and the contribution process

- Skill descriptions were put into a trigger form that says when to use them and their limits (#598).
- A third-party community tools page was added (#565, #538); these tools are not supported or audited by the project: https://github.com/avenoxai/avenoxbeyin/blob/main/docs/COMMUNITY-TOOLS.md
- The contributing guide and issue/PR templates were simplified by risk level (#450, #452); an inventory of source and distribution boundaries was added (#521).

## Verification

The release gate covers the full tests on Python 3.11 and 3.14, synthetic search evaluations, and update from the published 3.12.0 package and rollback. GitHub Actions verifies the package lifecycle for the same ZIP on Linux, macOS and Windows.

The Yakala agent, music recognition and the web view were not separately measured on a real desktop with this release's package. The earlier live trial for Pi covers only the Linux environment. Local tests are not proof of real client delivery.
