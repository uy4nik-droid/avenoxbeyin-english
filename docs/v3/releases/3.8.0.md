# AvenoxBeyin V3.8.0

This release collects the 26 PRs merged since 3.7.1. Highlights: a receipt can now be written with command-line flags without preparing JSON; in search, long summary notes no longer outrank the note that actually covers the topic (BM25); `supersedes` and retired statuses really remove old notes from the session context; and in multi-machine setups, two devices writing the same receipt ID with different content, and unresolved git conflict markers, are no longer silent but are reported as conflicts. Alongside these are many fixes for update, migration, the secret filter and the companion archive.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. After updating, open a new client session. Updating from a V3.7.1 install reports `trust_review_required: false`. For a fresh install, download `beyin-v3-3.8.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

If you sync the vault with git, add the line `**/.beyin-compact.lock` to `.gitignore` (details below, Companion archive).

## What's new

### Receipt

- **Command-line flags:** `python3 beyin.py receipt --harness claude --session <value> --event-id ID --summary "Result" --ref path.md`. `--ref` can be repeated; for a long summary use `--summary-file` (UTF-8). The summary and line breaks are preserved as they are; it cannot be used together with `--file`. The Stop reminder now suggests this format (#202).
- **Coverage window:** a turn after a receipt that only asks a question or says thanks no longer counts the session as "receipt missing" again. The window opens from the start of the last turn that edited files; if there is no edit, the old rule applies. An `edit_at` column was added to the local index; it does not break going back to 3.7.1 (#212, #237).
- **Line-ending warning:** if the vault is a git repository and `core.autocrlf=true` is set but there is no `-text` or `eol=lf` for `receipts/`, `doctor` shows an info line. Details in [MULTI-MACHINE.md](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/MULTI-MACHINE.md) (#205, #211).

### Multi-machine visibility

- **Conflict markers:** a file carrying `<<<<<<<`, `=======`, `>>>>>>>` markers (receipts included) is no longer indexed; `sync` returns `degraded` with an `unresolved git conflict markers` warning, and the file drops out of the context until it is resolved (#205, #207).
- **Receipt divergence:** a receipt written on another device with the same `event_id` but different content and arriving through a merge is reported as a `receipt_divergence` conflict; the local record is preserved (#205, #239).
- **Moved vault:** in a vault moved to another folder or account, hook files carrying old paths show up in `doctor` as `hook_paths: stale`; hook entries in PowerShell `-EncodedCommand` form arriving via git are recognized at install as Beyin's own entries and refreshed (#204, #238).

### Search and context

- **BM25 ranking:** non-strict searches (the `context` command, `retrieve`, `candidates`) are ranked with Okapi BM25 over stem counts; a long summary note that mentions each query word once no longer outranks the note that covers the topic. The thresholds of the per-turn (strict) context did not change (#214).
- **Consonant softening:** p/b and k/ğ reduce to the same stem: `kitabı`, `örneği`, `temizliği` now find the notes `kitap`, `örnek`, `temizlik`. No reindexing needed (#208, #209).
- **`supersedes` and retired statuses:** a `supersedes` value points to a note by explicit ID, vault path, `[[link]]` or unique file name, never by substring. A value that resolves to nothing, to multiple notes or to the note itself retires nothing and is reported as `supersedes` in `sync`/`doctor`. Notes whose status begins with `superseded`, `retired`, `archived`, `deprecated`, `obsolete`, `replaced`, `arşiv`, `eski`, `emekli`, `geçersiz` do not enter the context unless there is an explicit status filter (#201, #206).
- **The Kurallar.md truncation marker** names the skipped rule range; items in a code block do not count as rules (#196).

### Stop reminder

- Notes under `🧠 500-Knowledge/` and `500-Knowledge/` also count as distillation; a parenthetical explanation such as `Öğrenilen: yok (rutin kontrol)` does not change the answer (#197, #199).

### Companion archive

- `companion-compact` is serialized under the vault lock; when two processes compact at the same time, the archive can be rolled back (#193, #194). The lock is also shared between processes running with different runtime state or TMPDIR: a persistent `.beyin-compact.lock` file in the companion folder. The `.gitignore` line for git users is in [MULTI-MACHINE.md](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/MULTI-MACHINE.md) (#198).
- With a mixed date order, the newest stays on top, and archive entries end with a line break (#220); a code fence that closes on the same line no longer swallows the following headings (#228).

### Update, migration and recovery

- On read-only target files, the update temporarily takes write permission and puts the user's lock back; verification of turning off release notifications was hardened (#230).
- The lock check no longer produces an empty `memory.sqlite3`; rollback preserves file times (#222).
- The V2 migration reads alternative date formats and comma-separated labels, and an interrupted migration is rolled back (#224).
- In tasks, an explicit `status` and the ISO `updated_at`/`due_at` format are validated during `task-create` and `task-update`; records in an old vault do not drop out at `sync` (#226).

### Secret filter and bridges

- The `sk-` and `npm_` patterns respect word boundaries, real keys at the end of a sentence are also masked; URLs with an empty password are masked (#221). An `hf_` pattern and certificate blocks were added (#227).
- The bridge continues without shutting down on bad UTF-8 and a half-delivered payload, and records the error for `doctor`; omp sub-agents do not leak into the main session's record (#225).
- The Hermes turn counter was synchronized across threads, and dead marker temp files are cleaned up (#223); in memory evaluation, a `NaN` confidence value does not error, and pruning of continuity markers deletes the correct slice (#232).

### Test and CI

- A suite of front-end, budget and task edge cases (#200). The Windows CI time limit was raised to 25 minutes (#236).

## Verification

- Before release, 988 V3 tests passed on Python 3.11 and 3.14, also with the user's `BEYIN_*` settings on; the frozen retrieval gate (development 10/10, holdout 6/6) passed. The release pipeline verifies the same ZIP on Windows, macOS and Linux.
- A synthetic vault installed with the published V3.7.1 package was updated to this release (`trust_review_required: false`), and `verify_v3_release.py` passed with the V3.7.1 base. After rollback to V3.7.1, `doctor` and the SessionStart hook ran without errors.
