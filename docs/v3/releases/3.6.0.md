# AvenoxBeyin V3.6.0

This release is fix-heavy: the plugin reloads on OpenCode 2.x (#133, #150), `update` and `recover` that hung on pre-#114 Windows MSIX installs work (#139), the secret filter recognizes the keys of eight more common providers (#151), and sub-agent reports are no longer searched like user questions (#152). New and optional: folder-based project scoping for Jev (#141), a separate and wider context budget for session start (#140), and note-hygiene signals that are off by default (#129, #132).

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. After updating, open a new client session. Updating from a V3.5.1 install reports `trust_review_required: false`. For a fresh install, download `beyin-v3-3.6.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

**A vault stuck on Windows MSIX with `transaction target escapes root` (#139):** The updater of V3.5.1 and earlier cannot get past this error by itself. Close your agent sessions, download and unpack the V3.6.0 package, and from inside the package (from the agent's shell) run the installer twice with the existing state: `py -3 scripts/install_v3.py --vault "<vault>" --state "<state in .beyin-runtime.json>"`. The first run completes the interrupted operation, the second installs the new release. Details in the [update guide](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/UPDATE.md).

## What's new

### Clients and install

- **OpenCode 2.x:** the plugin supports both the 1.x and 2.x plugin APIs in a single file; on 2.x the hook bridge is no longer silently disabled (#133, #136, #150).
- **Windows MSIX:** `update`, `recover`, `rollback` and the installer that takes over a pending operation go through the same containment check. When, from inside the package, the root stays in the old spelling and files resolve under `LocalCache`, the target is accepted if its name is under the root and there is no symlink, junction or reparse point in between; `..`, absolute names and links that leave the root are still rejected (#139, #162).
- **Skill backups:** `skill-sync` backups and temporary copies are now under `.claude/.skill-backups` and `.agents/.skill-backups`; Claude Code no longer loads them as a second skill. Backups left in the skills folder by earlier releases are moved there at the next sync instead of being deleted (#157, #158).

### Hook and context

- **Synthetic turns:** sub-agent reports that begin with `<task-notification>` and messages coming from another session are not searched at UserPromptSubmit; the event record continues, and a normal user message still gets context. To turn it off, use `BEYIN_V3_FILTER_HARNESS_TURNS=0` (#152, #154).
- The hook does not crash even when the `prompt` field arrives as `null` or as a list of content blocks (#156).
- When the last receipt at session start is cut at 1,200 characters, it carries a `[truncated: read source]` marker (#144, #147).
- **Session-start budget:** when companion files are trimmed, the queryless "Related source" no longer takes their share (#140, #143). With `python3 beyin.py preferences --companion-context-chars 24000`, session start and continuity questions can be given a separate budget wider than 12,000. The setting is in the `companion-context.json` file in the runtime folder and does not enter `.beyin-preferences.json`; rollback is safe.
- **Continuity questions:** questions like "Kargo nerede kaldı?" (where did the cargo shipment get to?) do not trigger the companion context, while first-person return sentences such as "nerede kalmıştık" (where were we), "neler yapmıştık" (what had we done) and "tatilden döndüm" (I'm back from vacation) trigger it also when written in Turkish without diacritics and in uppercase (#145, #148, #151).
- In Threads files with an `## Açık konular` / `## Open` heading, closed topics do not enter the session-start context (#153, #159).
- For same-dated entries the newest is kept: `companion-compact` leaves the bottom-most update of the same day live in Threads, and in a single-dated Journal the bottom-most entry is selected (#163, #164). In the Journal summary, the newest undated entry is no longer lost (#134, #135).
- Companion trimming fills the share left over from line alignment with whole lines (#151).

### Security and privacy

- **Secret filter:** added Stripe (`sk_`/`rk_` live and test), Slack (`xox*`, `xapp`), Google API, npm, SendGrid, JWT/JWE and Discord bot token formats. Dotted formats match only when they stand alone; git SHAs, UUIDs, base64 and markdown links are left untouched (#151, #160).
- CI fails if a packaged module imports a helper that is not packaged (#151).

### Jev

- **Folder-based project scoping (optional):** in vaults whose notes have no `project` field, `.beyin-projects.json` at the vault root maps folders to projects; commands that take `--project` (`context --jev`, `jev-review`, `jev-memory`, `jev-answer`) use this scope. Matching is NFC and case-insensitive; if a folder in the setting does not exist in the vault, the command errors instead of leaking. Behavior is the same when the file is absent. Details in [JEV.md](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/JEV.md) (#141).
- When the `context --jev` candidate pool exceeds the budget, it is no longer dropped without going to the network; it is split into at most three packets. Passage heading parsing is linear, and headings with long runs of whitespace no longer lock up indexing (#142).

### Note hygiene (off by default)

- `doctor` gives read-only `boundary` and `closed_tasks` reports; vault-class folders (including Turkish spellings) are reported but not scanned (#129).
- Three opt-in signals: `preferences --word-cap-warning on --max-words 800`, `--folder-questions on`, `--promotion on`. The settings are in the `hygiene.json` file in the runtime folder; rollback is safe. Details in [PREFERENCES.md](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/PREFERENCES.md) (#130, #132).

### Test and CI

- Offline search benchmark dataset and measurement package (`scripts/evaluate_v3_search.py`); the asserts only catch regressions. The Windows CI job limit was raised to 15 minutes (#94, #138).

### Daily view

- `daily/v3/<day>.md` is now named by the local day of the timestamp; receipt timestamps and the `recap` window remain UTC. An old UTC-named view that is no longer produced is removed only if its bytes are identical to the record; a hand-edited file is not deleted (#149, #161).

## Verification

- Before release, 822 V3 tests passed on Python 3.11 and 3.14, together with the frozen retrieval gate (development 10/10, holdout 6/6). The release pipeline verifies the same ZIP on Windows, macOS and Linux.
- A synthetic vault installed locally with the published V3.5.1 package was updated to this release (`trust_review_required: false`), and `verify_v3_release.py` passed with the V3.5.1 base. Rollback to V3.5.1 was done with the new session-start budget on; `doctor` and the SessionStart hook ran without errors.
- Reproduced with a real install during review and fixed: in the first version of #143, `doctor` and the hooks crashed after rollback; in the first version of #141, the notes of a folder with a letter-case difference leaked into other projects; in #155, the fingerprint of the old V2 hooks was corrupted and the V3 migration stopped (PR closed, fix in #159).
