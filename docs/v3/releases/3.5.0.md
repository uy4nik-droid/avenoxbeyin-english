# AvenoxBeyin V3.5.0

This release supports working with multiple sessions and multiple machines in the same vault: each session keeps its own handoff card in `Last-Session.md` (#112, #116, #118), and there is a new guide for use on two machines (#122). It also adds a `recap` command with source links (#111), turning off unwanted skills and adapters (#108), project-specific session-start context for a project outside the vault (#117), a reminder for knowledge distillation (#109, #110), and pinning of the state path in Windows MSIX environments (#113, #114).

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. After updating, open a new client session. Updating from a V3.4.0 install reports `trust_review_required: false`. For a fresh install, download `beyin-v3-3.5.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

**Windows and MSIX (for example the Claude desktop app):** In a vault installed from inside MSIX with V3.4.0 or earlier, the pinned state path may have been written without redirection applied, and this does not fix itself. `doctor` now reports this under `state_location`. To fix it, re-run the installer **from inside the package** (from the agent's shell) with your existing `--state` value; steps are in the [update guide](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/UPDATE.md).

## What's new

### Parallel sessions and multiple machines (#112)

- `Last-Session.md` consists of one handoff card per session: `## YYYY-MM-DD HH:MM · <label> · <session_id[:8]>`. Each session edits only its own card; the `AGENTS.md` block, the `CLAUDE.md` template and the `beyin` skill state the same rule (#116).
- `companion-compact` sorts cards by the date in the heading. A dated item or subheading inside a card no longer splits the card, and the "Sıradaki" (Next) part no longer goes to the archive (#118, #121).
- New guide [Multiple machines](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/MULTI-MACHINE.md): which files go into git and which do not, the recommended `.gitignore` and `.gitattributes` (`receipts/** -text`, `merge=union` for companion files), working on two machines on the same day, and a unique `event_id` across machines (#122).
- Note added to the README: Claude Code deletes local chat records after 30 days by default, so lasting knowledge must be written to a note (#123).

### Source-linked summary: `recap` (#111)

- `python3 beyin.py recap --days 7` lists the receipts of recent days, newest to oldest, with source links. It makes no model call.
- Links to private notes are hidden, deleted sources are not listed, and terminal escape sequences are cleaned.

### Component and skill exclusion (#94 item 7, #108)

- With commands like `python3 beyin.py preferences --exclude-component skills/beyin-doktor`, startup skills, adapters, launchers or the Antigravity hook can be turned off; `--include-component` turns them back on.
- The list lives in the `.beyin-exclusions.json` file and does not touch `.beyin-preferences.json`; so rollback to V3.4.0 is safe. Files the user changed are preserved, and install does not lock up even if `CLAUDE.md` is a symlink.

### Project-aware session start (#94 item 1, #117)

- With `python3 beyin.py preferences --project-context on`, the [global bridge](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/GLOBAL-BRIDGE.md) adds that project's newest receipt summary and its due tasks to a session opened in a project outside the vault. It is off by default.
- `private` and untrusted sources are not included; other projects' task titles are not given, only their counts are written. The setting is in the `project-context.json` file in the runtime folder.

### Knowledge distillation (#109, #110)

- If a receipt declares `Öğrenilen: <single sentence>` (Learned) but no note was written under `knowledge/` in the session, the Stop hook reminds about distillation once per session.
- `doctor` writes how many days ago the last distillation was done and how many receipts have accumulated since then. It warns if an old V2 phrase that leaves the `knowledge/` folder to the compiler remains in `AGENTS.md` or `CLAUDE.md`.

### Memory and tasks

- The Jev advisor flags a claim that restates a rejected inference with the `previously_rejected` diagnosis and routes it to `inspect_sources`; it blocks nothing (#107).
- `rejected_at` also accepts an ISO timestamp, and the result does not depend on the Python version (#104).
- In an update that sets a strict task to `done`, the completion criterion cannot be changed (#105).
- `doctor` reports `validity` fields that are ignored because of the record's type (`kind`) (#106).

### Doctor

- Broken in-vault links in instruction and skill files are reported as information; the resolver behaves like Obsidian (#103).
- State location: a warning for a split state root or one left inside a container, and a state migration guide (#113, #115).
- OMP: a stale `beyin-v3.ts` copy left in the global agent folder is reported as information; the file is not touched (#124).

### Windows

- After creating the state root, the installer resolves and pins it; in an MSIX container, processes inside and outside the package see the same directory (#113, #114).
- In a V2 vault, the stock doctor skill under `.agents` is also exempted during migration (#119).
- On Windows and Python 3.14, the Jev tests preserve `SYSTEMROOT` in a cleaned environment (#126).

## Verification

- Before release, 713 V3 tests passed on Python 3.11 and 3.14, together with the frozen retrieval gate (development 10/10, holdout 6/6). The release pipeline verifies the same ZIP on Windows, macOS and Linux with Python 3.11 and 3.13: clean install, migration from the published V3.0.2 and V3.1.0 packages and from the `cad7953` install, no-op, read-only, rollback, recovery of an interrupted operation, and preservation of user notes.
- A synthetic vault installed locally with the published V3.4.0 package was updated to this release (`trust_review_required: false`), and `verify_v3_release.py` passed with the V3.4.0 base. Rollback to V3.4.0 was done with `project-context` on and a skill excluded; `doctor` and the SessionStart hook ran without errors.
