# AvenoxBeyin V3.5.1

A release preparing for a repository rename: the updater now recognizes both official repository names (`avenoxai/avenoxbeyin` and `avenoxai/beyin`). The repository has not been renamed right now; everyone is advised to move to 3.5.1 so that updating does not break after a possible name change.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. Updating from a V3.5.0 install reports `trust_review_required: false`. For a fresh install, download `beyin-v3-3.5.1.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

## Why

GitHub redirects the old API address of a renamed repository to the new address, but the download links in the response (`browser_download_url`) carry the new name. Because V3.5.0 and earlier compared this link exactly against the old name (`beyin_v3_releases.py`, `release_metadata`), they could not update after a rename, failing with an `invalid_asset` error.

## Change

- Only two fixed repository names are accepted for the package and `.sha256` link: `avenoxai/avenoxbeyin` and `avenoxai/beyin`. The exact-match, tag and filename checks continue unchanged for each name. Any other name (for example `avenoxai/beyin-evil` or a different account), and a different name between the package and its `.sha256`, is rejected.
- The release information address did not change; if the name changes, the redirect from the old address is followed. The redirect can only go to GitHub addresses.
- No new field was added to the preferences file; rollback to V3.5.0 and V3.4.0 is safe.

## Verification

- 715 V3 tests passed on Python 3.11 and 3.14. The new tests cover acceptance of the two names, rejection of a third name and of mixed names, and following the API redirect of a renamed repository.
- A synthetic vault installed locally with the V3.5.0 package was updated to this release and rolled back.
