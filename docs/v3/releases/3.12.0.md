# AvenoxBeyin V3.12.0

The 33 contributor PRs and maintainer fixes that landed on main after 3.11.0 are collected in this release. Yakala saves multiple links and an optional window screenshot together; the Windows listener recovers from transient errors, and browser address reading support is broader. For agents on the same machine, hash-checked note editing, a read-only memory audit, a learning candidate ledger and an optional flat daily layout arrived. Project rules are selected from the working folder, and person notes enter the startup context when they match the question.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. For a fresh install, download `beyin-v3-3.12.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

**If you use Yakala**, run `python3 beyin.py yakala kur` once after updating (`py -3` on Windows; if you use only the template and skill, add `--kisayol-yok` (no shortcut)). `kur` refreshes the separately copied listener/window script and the `beyin-yakala` skill; the update does not reinstall these copies. This way you also get the Windows broker fixes and the multi-link guidance. Your shortcut and inbox choice are preserved.

**Hook definitions:** when moving from a clean 3.11.0 install to this release, the vault hook definitions do not change; the Codex `/hooks` review is not needed just for this update. If you are coming from an older release or the install paths changed, complete the trust step for the client that the update reports. The update does not produce trust approval. Open a new session in the client for the refreshed engine and skills.

**If you sync the vault with git**, add the line `.beyin-note-write/` to your `.gitignore` file. This folder holds the machine-local write lock, temporary edit requests, and backups that carry note content; keep it out of cloud sync as well. Do not delete the persistent `writer.lock` file by hand. The new `.beyin-daily-layout.json`, on the other hand, is a shared preference belonging to the vault and can be synced with git.

**The flat daily layout is optional:** by default it stays `daily/v3/DAY.md`. If you like, choose `daily/DAY.md` with `python3 beyin.py preferences --daily-layout flat`; to go back, use `--daily-layout v3`. First bring the machines that write to the same vault to this release. The setting does not change the `.beyin-preferences.json` schema; after rollback to 3.11.0 the old engine ignores the setting and produces its own `daily/v3/` view. Flat views are kept in a separate ownership table and may remain as files after going back.

## What's new

### Yakala

- **Joint source selection (#434):** multiple links can be added to the same card. The main address is kept in `url`, the others in `ek_urller` (extra URLs) and the `## Ek bağlantılar` (extra links) section; `yakala isle` processes the main address. Different URL forms of the same source do not create a second option. The window screenshot can be selected even when there is a link, but it is not added automatically. If one of the extra addresses is a mail page, the card stays `private`.
- **Window and shortcuts (#434):** Alt shortcuts also work in the note box; Caps Lock and Turkish I/İ are handled. Source cards follow the system theme, and the list scrolls when there are many sources. Old clipboard text is not offered as a source option on every open.
- **Windows listener (#435):** the ready-window protocol and close ownership were hardened. On a transient handshake timeout or connection error, the listener prepares the window again without dropping the shortcut; on the third transient error within 120 seconds, it shuts down. The final ACTIVE/DONE packets racing with EOF and dropping a valid capture was fixed with maintainer fixes. A capture whose outcome is uncertain is not resent automatically.
- **Windows post capture (#383):** in the X/Instagram feed, the real post link under the cursor is read; `Alt+A` adds the post text as an optional quote. Esc closes the open yakala window even when focus is elsewhere. The title of an X card uses the `@username: text` format.
- **Browser address (#399, #413):** on Windows, a Firefox/Zen address reader and a UI Automation wake-up for Opera Air were added. On macOS, accessibility (AX), and on Linux X11, address reading through the active window were added. If permission or support is missing, the page address is not guessed; the clipboard and manual entry can be used. The X11 reader is not valid for Linux Wayland.
- **Source safety (#396, #422):** the Python stdlib HTTP path pins a direct connection to the validated DNS answer; if a proxy is used, address resolution stays on the proxy side. The `--` separator is used in the arguments of external helpers; untrusted-content boundaries were hardened. This does not provide isolation for all network access of external helpers.

### Safe note editing on the same machine

- **`note-read` / `note-edit` (#412):** `python3 beyin.py note-read "folder/note.md"` returns the text and the raw-byte SHA-256 as JSON. Then use `python3 beyin.py note-edit --file request.json` (`--file -` reads stdin). A request for an existing note carries `source`, `expected_sha256` and `edits: [{old, new}]`; each `old` must occur exactly once. For a new note, use `expected_sha256: null` and `content`.
- **Conflict protection:** the hash is checked under an in-vault operating system lock, the previous bytes are backed up, and the file is replaced atomically. Exit code 0 means `written` / `unchanged`, 2 means `conflict`, 1 means `error`. On a conflict, the note is read again and the other agent's change is preserved. BOM and CRLF are preserved; tasks, receipts, generated views, configuration and paths outside the vault are not edited with this API. This lock coordinates only writers on the same machine that use these commands; it does not solve concurrent editing with Obsidian or writers on other machines.

### Memory audit and learning candidates

- **Read-only auditor (#388):** `python3 beyin.py audit` gives suggestions for similar notes and possible status contradictions using local lexical analysis; it does not modify or delete notes and makes no model call. For a single note, `audit knowledge/note.md` can be used. Defaults are `--threshold 0.60`, `--min-shared 5`, `--limit 20`; private and untrusted sources are not taken into the candidate pool. The findings are not independently verified facts.
- **Candidate ledger (#395):** `python3 beyin.py learn --candidate "Learning candidate" --source knowledge/note.md` records the candidate in the `learning-state.jsonl` file inside the runtime; `learn --list` lists, and `--scope` selects the scope. A candidate does not turn directly into a lasting knowledge note. Source trust is checked and the secret filter is applied. In a session where files were edited, writing only `Öğrenilen: yok` in the receipt is queried once; a candidate recorded or a knowledge note written in that edit window satisfies the learning requirement.

### Context and search

- **Project rules (#387, #404):** the hook and bridge project resolver maps the working folder inside the vault using `.beyin-projects.json` mappings or the `projects/`, `Projeler/`, `projeler/` folders. This way the relevant `projects/<project>/Kurallar.md` can be taken into context in Claude Code as well; selecting by cwd does not limit general note search to that project. Robustness was increased for an invalid working folder, symlink loops and NTFS junctions.
- **Person notes (#391, #436):** visible person cards are added to the context; a card named in the question can be selected even if it falls outside the top five. At a startup without a question, the five-person limit is kept. When Last-Session is compacted, an archive pointer is kept.
- **When sync is deferred (#400):** the hook keeps bringing context from the last usable index; a warning that the source may be behind is also added to the Jev output. No network call is made when Jev is off.
- **Turkish search (#430, #438):** inflections such as `kurulmalı`, `kuruldu`, `kuruluyor` and vowel drops such as `beyin/beyni`, `şehir/şehri` match. The `Claude` name being wrongly cut to the stem `clau` was fixed; existing matches such as `tarih/tarihte` were preserved. Turkish morphology is not considered fully supported.

### Install, bridge and resilience

- **Flat daily view (#411):** the `flat` layout does not overwrite a daily file written by a person; the view is skipped for that day, and receipt summaries stay in the outcomes view. On a layout change, only an old view identical to the recorded hash is removed; an edited file is preserved and can be recovered, archived, with `sync --recover-views`. A corrupt daily preference does not crash sync and the hooks; the last view is preserved.
- **Global bridge management (#405, #440):** `python3 beyin.py bridge --harness antigravity --project-root "/full/path/MyProjects" --install` installs the global hook and a scoped `GEMINI.md` instruction; `--uninstall` removes it. `--harness` is also selectable for Claude and Codex. Existing files are protected with a `.bak` backup; corrupt JSON is not overwritten, and foreign hooks are not deleted. `--print-config` shows the configuration without writing to disk. Antigravity is not a new client; it is also supported in 3.11.0. Global settings are not within the scope of a vault rollback; if you want to remove the bridge as well, run `bridge --harness antigravity --uninstall` before the rollback.
- **V2 migration and paths (#431, #393, #402, #442):** old stock runner/doctor copies and hook JSON files with a BOM are recognized. An invalid state pin, symlink loops, Unicode paths and closing ingest connections are handled more robustly. The V2 hook templates were not changed.
- **Hook and CLI errors (#418, #410, #439):** even if the error log cannot be written, a lifecycle hook does not stop the client. If a hook definition changes, the update shows only the relevant client's trust step. With `--json`, argument usage errors give JSON on stderr and exit code 2; `--help` keeps the normal help output.
- **Internal maintenance (#426, #441, #447):** the query and adjacent runtime module loading paths were fixed; standalone sync/search and the semantic evaluation find the same modules. The Windows test environment also preserves the system drive variables. A contributing guide was added (#437): https://github.com/avenoxai/avenoxbeyin/blob/main/CONTRIBUTING.md

## Verification

- On macOS, the full `v3_*test.py` suite separately on Python 3.11 and 3.14: **2316 tests OK** (39 skipped in each run). The Python 3.11 run with `BEYIN_V3_SKIP=1 BEYIN_V3_INTERNAL=1` was also **2316 tests OK** (39 skipped).
- `scripts/evaluate_v3.py`: **10/10 development and 6/6 holdout** passed; privacy canary leakage 0. These are synthetic, offline search and persistence scenarios.
- For the same local ZIP, checksum/manifest, clean install, update from the published 3.11.0 ZIP, read-only check, no-op on the same release, rollback, recovery from interruption and preservation of user notes passed with `verify_v3_release.py`.
- 3.11.0 was installed in an isolated HOME and a temporary vault and updated to 3.12.0; doctor and the installed Claude SessionStart command ran. A flat daily and a receipt were produced; `learn`, `note-read`, `note-edit`, `audit` and the Antigravity bridge install/uninstall commands were tried. After rollback to 3.11.0, doctor, SessionStart and sync passed; no pending event, hook error, view conflict or sync warning was left. The edited user note and the flat daily were preserved, and the old engine also produced the `daily/v3/` view.
- In the same install, the Claude, Codex, Antigravity and Kiro vault hook JSONs stayed the same as before the update; `trust_review_required: false` was returned. So no new trust approval was needed in the client.
- In this round, the new Firefox/Zen, macOS AX and X11 readers and the popup view were not measured on a real desktop; local tests are not a substitute for real client delivery or device verification.
