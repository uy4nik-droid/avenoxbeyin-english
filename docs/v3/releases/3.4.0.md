# AvenoxBeyin V3.4.0

The context added with every message now brings the section that carries the answer, not the start of the note (#83). This release also adds a size limit and lossless compaction for `Last-Session.md` and `Threads.md` (#96), a receipt reminder at Stop time (#95), removal of rejected inferences from context (#91), an optional completion contract for tasks (#92), and a fix for installs left half-finished on Windows (#97).

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. After updating, open a new client session. The managed hook definition files did not change in this range; updating from a V3.3.0 install reports `trust_review_required: false`. For a fresh install, download `beyin-v3-3.4.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

## What's new

### Passage-level per-turn context (#83, #99)

- Strict search does not score a note as a single bag of words. It splits the note into Markdown blocks and, from each source, delivers the block that best matches the question, together with its heading path. If the answer is in the middle of a long note, the block carrying the answer arrives, not the first characters of the note. A long session archive that contains almost every word also cannot rise to the top on every question.
- Long messages written in a conversational tone are not filtered out because of their length. There is no model call and no new dependency.
- Settings are machine-specific and live in the `retrieval.json` file in the runtime folder: `strict_floor` (default 0.20) and `strict_exclude` (`daily/` and `receipts/` are always excluded). The index is kept outside the vault as `passages.json`; the first build runs for at most about one second per turn and resumes where it left off.
- Measurement (`scripts/evaluate_v3_passages.py`, the hook's delivery path, the answer sentence appearing verbatim in the delivered text): on the synthetic corpus, short questions went from 24/42 to 33/42 at a 5000 budget, and long messages from 20/42 to 28/42. On a read-only copy of a vault (1,285 notes, 264 queries), the count at a 5000 budget went from 60 to 160; unnecessary additions on casual check-in messages fell from 4/20 to 1/20.
- `pack_context` now allots a fair share per record; a single long record can no longer consume the entire budget (#79, #81).

### Size limit for Companion files (#96, #100)

- There is a limit of 3,000 characters for `Last-Session.md` and 8,000 for `Threads.md`. Change it with `preferences --last-session-chars N --threads-chars N`; `0` turns the limit off.
- When the limit is exceeded, the session context starts with a one-line `Memory hygiene:` warning; `doctor` shows the file sizes under `companion_hygiene`.
- `beyin.py companion-compact [--dry-run]` moves old entries, losslessly, to `<companion>/Arşiv/<File>-YYYY-MM.md` (`visibility: private`). It does not run automatically; no hook or timer triggers it. The agent instructions now also tell it to rewrite the card instead of appending to these files on every message.

### Receipt reminder at Stop time (#95)

- If files were edited in the session and no receipt was written with the same client and the same `session` value after the edits, the hook stops Stop once per session and reminds the agent of the receipt command with the `Receipt session=<value>` information. Edits are tracked from the PostToolUse event; the transcript is not read.
- To turn it off: `[kaydetme]` in a user message for that session, `BEYIN_V3_NO_RECEIPT_REMINDER=1` entirely. Details: [preferences](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/PREFERENCES.md).
- For delegated or headless runs, `BEYIN_V3_SKIP=1` silences the hook and the bridge; only the exact value `1` is valid (#93).

### Memory and tasks

- Optional `validity: current|rejected` for `kind: inference` and `kind: preference` records. Rejected records do not enter any context path, their history can still be seen with `history RECORD_ID`; the audit trail of deleted records is preserved (#91).
- Optional `completion_contract: strict` for tasks: `done` requires a non-empty `completion_criterion` and at least one `evidence_refs` path that exists inside the vault. Tasks without a contract work as before (#92).
- `doctor` shows the receipt coverage rate for all time, 7 days and 30 days (#80).
- When the local state folder is reset, the receipts on disk are restored; the permanent `ReceiptConflict` lockup in earlier releases is gone (#75).

### Security and Jev

- The secret filter also catches quoted and escaped key values, URL query values, database URI passwords and free-text fields in task metadata (#76).
- Calls from the Jev advisor to local addresses (`127.0.0.1`, `::1`) no longer go through the system HTTP proxy setting (#98).
- An optional local Laya provider was added, in shadow mode only (#101). In our measurements, zero-shot Laya fell clearly below Jev on these tasks; for that reason its scores do not change what the user sees. Details and measurement: [Jev guide](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/JEV.md).

### Windows

- Install being left half-finished with a `transaction target escapes root` error under MSIX-virtualized `AppData` (for example the Claude desktop app) is fixed (#97).

## Verification

- 598 V3 tests and the unchanged frozen retrieval gate (development 10/10, holdout 6/6) run before release. The release pipeline verifies the same ZIP on Windows, macOS and Linux with Python 3.11 and 3.13: clean install, migration from the published V3.0.2 and V3.1.0 packages and from the `cad7953` install, no-op, read-only, rollback, recovery of an interrupted operation, and preservation of user notes.
- Before release, a synthetic vault installed locally with the published V3.3.0 package was updated to this release (`trust_review_required: false`), and `verify_v3_release.py` passed with the V3.3.0 base.
- The Windows-specific #97 fix was verified in the Windows cells in CI and on the contributor's Windows 11 / Python 3.14 machine.
