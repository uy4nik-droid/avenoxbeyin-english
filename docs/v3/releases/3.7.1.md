# AvenoxBeyin V3.7.1

Two update fixes. After an update, `doctor` and the session-start notification wrongly showed the installed release as "ahead of the official release" for 24 hours (#188). Also, for those syncing the vault across multiple machines with git, managed files that had already arrived up to date from the other machine stopped the update with a "Reinstall conflict" (#189).

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. Updating from a V3.7.0 install reports `trust_review_required: false`. For a fresh install, download `beyin-v3-3.7.1.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

## Fixes

- **Release status (#188, #190):** On a network update, the release cache is refreshed with the downloaded release's information; it is cleared after `--package`, rollback and recover. A check made before the install and left behind by an old updater is no longer counted as "ahead"; a fresh check starts in the first session. For this reason the wrong message does not appear when moving from 3.7.0 to 3.7.1 either. The cache schema did not change, so rollback is unaffected.
- **Multi-machine update (#189, #191):** If a managed file on disk is the same as the content to be written (differing only in line endings), it is no longer counted as a conflict; in 3.7.0 this applied only to `AGENTS.md` and `CLAUDE.md`. A real user edit (including BOM and whitespace) still produces a conflict and the file is not touched.

## Verification

- Before release, 875 V3 tests passed on Python 3.11 and 3.14, also with the user's `BEYIN_*` settings on; the frozen retrieval gate passed. The release pipeline verifies the same ZIP on Windows, macOS and Linux.
- A synthetic vault installed with the published V3.7.0 package was updated to this release (`trust_review_required: false`), `verify_v3_release.py` passed with the V3.7.0 base, and after rollback `doctor` and SessionStart are clean.
- The two-machine scenario (the 3.6.0 and 3.7.0 release packages, separate state folders) and the release status after updating from 3.6.0 were tested with a real install.
