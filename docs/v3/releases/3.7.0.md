# AvenoxBeyin V3.7.0

The main subject of this release is the session-start context actually reaching the client. Claude Code moves hook context over 10,000 characters, and Codex over 10,000 bytes, into a file and shows the model only a part of it; with the wide startup budget suggested in 3.6.0, Last-Session, Threads and Journal were dropping out of the automatic context (#175). Now the context stays under this limit in both clients. In addition, a receipt tied to a private note no longer enters session start, `companion-compact` takes a full backup on the rewrite path, `recover` no longer hangs after a successful V2 migration, and two optional features arrived: parallel-session notification and a usage report.

## Existing users: update once

In the vault folder on macOS / Linux:

```sh
python3 beyin.py update
```

Windows:

```powershell
py -3 beyin.py update
```

Telling your agent "update my brain" also runs the same command. After updating, open a new client session. Updating from a V3.6.0 install reports `trust_review_required: false`. For a fresh install, download `beyin-v3-3.7.0.zip` and the `.sha256` file next to it; do not use GitHub's Source code archive.

If you set `--companion-context-chars 24000`, the context is still held at 9,500 in Claude Code and Codex; you do not need to change the setting. In other clients the setting applies as is.

## What's new

### Session-start context

- **Client limits:** for Claude Code (10,000 UTF-16 characters) and Codex (10,000 UTF-8 bytes), the startup and turn context is held at 9,500; if the Codex limit is exceeded because of Turkish letters, the context is regenerated with a smaller budget, so trailing sections are not lost. The skill suggestion went down from 24,000 to 8,000. `.codex/hooks.json` did not change, so Codex hook trust is unaffected (#175, #176, #186).
- **Kurallar.md (the rules file):** at startup, all the rule sentences come first; if the share is not enough, the `**neden:**` / `**gerekçe:**` (reason) parts are dropped and their count is written. The "first 60 lines" paragraph from the V2 template is removed from the startup view; your file is not touched (#177, #184).
- **Knowledge map share** scales with the free space when there is room; when the companion is trimmed, it stays at its old share (#146, #167).
- **Last receipt:** the heading names the source file and is added only with its full title (#147, #174); it is selected by the `created_at` value, not by file time, so `git pull` does not disturb the order (#112, #186).
- **Privacy:** a receipt tied to a private (`visibility: private`) or untrusted note no longer enters SessionStart inside the vault either; the same rule as the bridge (#186).

### Update, migration and recovery

- `recover` no longer hangs with `source or legacy state changed during migration` when a note changes in an update left half-finished after a successful V2 migration. The source check stays as is on a real first migration. For a vault already stuck on an older update: first `beyin.py rollback`, then `beyin.py update` (#181, #182).
- The AGENTS block does not carry a machine path (`python3 beyin.py sync`); it comes out the same on two machines, and a new block arriving via git does not stop the other machine's update (#112, #186).

### Companion archive

- When `companion-compact` says `needs_rewrite`, before the agent rewrites the file, the full text is written word for word to the monthly `Arşiv/<File>-YYYY-MM.md` file (the archive); also for a file that still exceeds the limit after a partial move. `--dry-run` writes nothing and does not behave as if a backup exists (#168, #171).

### Sync

- Single-level nested YAML in frontmatter (`key: value` under `metadata:`) is read; notes like Claude auto-memory now enter the index. If privacy keys such as `visibility` and `trust` are written nested, they are not applied, so the note is left out with a warning (#179, #180).

### New optional features

- **Parallel-session notification:** a one-line warning in the first prompt if another session is open in the same vault. Off by default: `python3 beyin.py preferences --parallel-sessions on`. The markers are in the runtime folder; the prompt text is not written (#170, #183).
- **Usage report (developer tool):** `scripts/evaluate_v3_usage.py` counts, read-only, from Claude Code transcripts whether injected notes were opened afterward; it is not part of the release package. Details in [USAGE-REPORT.md](https://github.com/avenoxai/avenoxbeyin/blob/main/docs/v3/USAGE-REPORT.md) (#172, #185).

### Test and measurement

- The test suite does not inherit `BEYIN_*` settings from the parent environment (#169, #186).
- The search benchmark report was cleaned up, and a control row with `daily/` excluded was added (#173).

## Verification

- Before release, 871 V3 tests passed on Python 3.11 and 3.14, also with the user's `BEYIN_*` settings on; the frozen retrieval gate (development 10/10, holdout 6/6) passed. The release pipeline verifies the same ZIP on Windows, macOS and Linux.
- A synthetic vault installed locally with the published V3.6.0 package was updated to this release (`trust_review_required: false`), and `verify_v3_release.py` passed with the V3.6.0 base. Rollback to V3.6.0 was done with the parallel-session notification and the wide startup budget on; `doctor` and the SessionStart hook ran without errors.
- In a real Claude Code session with the 24,000 setting, SessionStart now arrives as 9,500 characters without being moved to a file.
